## 🤔 Что такое React Native?

**React Native** - это фреймворк от Facebook (Meta) для создания мобильных приложений.

### Зачем он нужен?

**Проблема:** Раньше для создания мобильного приложения нужно было писать код дважды:
- На **Swift/Kotlin** для iOS
- На **Java/Kotlin** для Android

**Решение:** React Native позволяет писать код **один раз** на JavaScript, и он будет работать на обеих платформах!

### Как это работает?

React Native использует "мост" (bridge), который:
1. Выполняет JavaScript код
2. Переводит его в нативные команды для iOS/Android
3. Отображает результат на экране

**Аналогия:** Представь переводчика, который переводит твои слова с русского на английский и китайский одновременно.

## 🚀 Что такое Expo?

**Expo** - это набор инструментов и сервисов, который **максимально упрощает** разработку React Native приложений.

### Почему Expo - это хорошо?

#### ❌ Без Expo (чистый React Native):
- Нужно устанавливать Android Studio (5+ ГБ)
- Нужно устанавливать Xcode (только на Mac, 10+ ГБ)
- Нужно настраивать эмуляторы
- Нужно компилировать нативный код
- Много времени на настройку окружения

#### ✅ С Expo:
- Устанавливаешь Node.js и Expo CLI
- Скачиваешь приложение Expo Go на телефон
- Запускаешь `npm start`
- Сканируешь QR-код
- **Готово!** Приложение работает на твоем телефоне

### Что дает Expo?

1. **Expo Go** - приложение для тестирования без компиляции
2. **Expo Router** - навигация на основе файловой системы
3. **Готовые API** - камера, геолокация, уведомления и т.д.
4. **Простая публикация** - один команда для публикации в App Store/Google Play

**Вывод:** Expo = меньше геморроя, больше времени на код!

## 📁 Структура проекта

Давай разберем, что у нас есть:

```
React native/
├── app/                    # Папка с экранами (Expo Router)
│   ├── _layout.js         # Главный layout с навигацией
│   ├── index.js           # Главный экран (/)
│   ├── profile.js         # Экран профиля (/profile)
│   └── details.js         # Экран деталей (/details)
├── components/            # Переиспользуемые компоненты
│   └── Card.js            # Компонент карточки
├── package.json           # Зависимости проекта
├── app.json              # Конфигурация Expo
├── babel.config.js       # Настройки Babel (транспилятор)
└── README.md             # Этот файл
```

### Почему такая структура?

**Expo Router** использует **файловую систему для маршрутизации**:
- `app/index.js` = главный экран (путь `/`)
- `app/profile.js` = экран профиля (путь `/profile`)
- `app/details.js` = экран деталей (путь `/details`)

**Это как роутинг на вебе, но для мобильных приложений!**

## 🧩 Основные концепции

### 1. Компоненты

**Компонент** - это кусок кода, который возвращает что-то визуальное (UI).

**Аналогия:** Компонент = LEGO блок. Из маленьких блоков собираешь большую конструкцию.

#### Пример простого компонента:

```javascript
import { View, Text } from 'react-native';

function MyComponent() {
  return (
    <View>
      <Text>Привет, мир!</Text>
    </View>
  );
}

export default MyComponent;
```

**Что здесь происходит?**
- `View` - это как `<div>` в HTML, контейнер
- `Text` - это как `<p>` в HTML, текст
- Функция возвращает JSX (HTML-подобный синтаксис)

### 2. JSX - что это?

**JSX** - это синтаксис, который выглядит как HTML, но это JavaScript.

```javascript
// Это JSX:
<View>
  <Text>Привет</Text>
</View>

// Это то же самое, но без JSX (неудобно):
React.createElement(View, null, React.createElement(Text, null, "Привет"))
```

**Правила JSX:**
- Всегда закрывай теги: `<View></View>` или `<View />`
- Используй `className` → `style` (в React Native)
- JavaScript выражения в `{ }`: `<Text>{name}</Text>`

### 3. Импорты и экспорты

**Импорт** - берешь что-то из другого файла:
```javascript
import { View, Text } from 'react-native';  // Берем из библиотеки
import Card from './components/Card';       // Берем из своего файла
```

**Экспорт** - отдаешь что-то другим файлам:
```javascript
export default MyComponent;  // Отдаем компонент
```

## 🎨 Компоненты

### Базовые компоненты React Native

#### 1. `<View>` - Контейнер
```javascript
<View style={{ padding: 20 }}>
  <Text>Контент</Text>
</View>
```
**Зачем:** Группирует элементы, как `<div>` в HTML.

#### 2. `<Text>` - Текст
```javascript
<Text style={{ fontSize: 18 }}>Какой-то текст</Text>
```
**Зачем:** Отображает текст. **Важно:** В React Native весь текст должен быть внутри `<Text>`!

#### 3. `<TouchableOpacity>` - Кнопка
```javascript
<TouchableOpacity onPress={() => console.log('Нажато!')}>
  <Text>Нажми меня</Text>
</TouchableOpacity>
```
**Зачем:** Создает кнопку, которая реагирует на нажатие.

#### 4. `<TextInput>` - Поле ввода
```javascript
<TextInput
  value={text}
  onChangeText={setText}
  placeholder="Введите текст"
/>
```
**Зачем:** Позволяет пользователю вводить текст.

#### 5. `<ScrollView>` - Прокручиваемый контент
```javascript
<ScrollView>
  <Text>Много контента...</Text>
  <Text>Который не помещается на экран</Text>
</ScrollView>
```
**Зачем:** Позволяет прокручивать контент, если он не помещается.

### Создание своих компонентов

**Зачем создавать свои компоненты?**
- Переиспользование кода
- Чистота и читаемость
- Легче поддерживать

**Пример:**
```javascript
// components/Card.js
export default function Card({ title, children }) {
  return (
    <View style={styles.card}>
      <Text style={styles.title}>{title}</Text>
      <Text>{children}</Text>
    </View>
  );
}

// Использование:
<Card title="Заголовок">Содержимое карточки</Card>
```

## 💅 Стили

### StyleSheet - что это?

**StyleSheet** - это способ создания стилей в React Native. Похоже на CSS, но есть отличия.

### Зачем StyleSheet, а не обычные объекты?

```javascript
// ❌ Плохо (создается новый объект при каждом рендере):
<View style={{ padding: 20 }}>

// ✅ Хорошо (объект создается один раз):
const styles = StyleSheet.create({
  container: { padding: 20 }
});
<View style={styles.container}>
```

**Почему:** StyleSheet оптимизирует стили и делает приложение быстрее.

### Основы стилей

#### Flexbox - основа расположения

React Native использует **Flexbox** по умолчанию. Это система для расположения элементов.

**Основные свойства:**

```javascript
{
  flex: 1,                    // Занимает все доступное пространство
  flexDirection: 'column',    // 'row' - в ряд, 'column' - в столбец
  justifyContent: 'center',   // Выравнивание по главной оси
  alignItems: 'center',      // Выравнивание по поперечной оси
}
```

**Визуализация:**
```
flexDirection: 'column' (по умолчанию)
┌─────────────┐
│   Элемент 1 │
│   Элемент 2 │
│   Элемент 3 │
└─────────────┘

flexDirection: 'row'
┌─────────────────┐
│ Эл1 │ Эл2 │ Эл3 │
└─────────────────┘
```

#### Цвета

```javascript
{
  backgroundColor: '#6200ee',  // Фон
  color: '#fff',               // Цвет текста
  borderColor: '#ddd',          // Цвет границы
}
```

#### Размеры

```javascript
{
  width: 100,        // Ширина
  height: 50,        // Высота
  padding: 20,       // Внутренние отступы
  margin: 10,        // Внешние отступы
  borderRadius: 8,   // Скругление углов
}
```

#### Тени (тень для iOS и Android)

```javascript
{
  // iOS
  shadowColor: '#000',
  shadowOffset: { width: 0, height: 2 },
  shadowOpacity: 0.1,
  shadowRadius: 4,
  
  // Android
  elevation: 3,
}
```

### Пример стилей из проекта

```javascript
const styles = StyleSheet.create({
  container: {
    flex: 1,                    // Занимает весь экран
    backgroundColor: '#f5f5f5', // Светло-серый фон
  },
  button: {
    backgroundColor: '#6200ee', // Фиолетовый фон
    padding: 16,                // Внутренние отступы
    borderRadius: 8,            // Скругленные углы
    alignItems: 'center',       // Текст по центру
  },
});
```

## 🧭 Навигация

### Что такое навигация?

**Навигация** - это переход между экранами в приложении.

**На вебе:** Переход по URL (`/profile`, `/about`)
**В мобильном:** Переход между компонентами (экранами)

### Expo Router - файловая система = маршруты

**Идея:** Структура папок = структура приложения

```
app/
├── index.js      → Главный экран (/)
├── profile.js    → /profile
└── details.js    → /details
```

### Как переходить между экранами?

#### 1. Использование `useRouter`

```javascript
import { useRouter } from 'expo-router';

function MyComponent() {
  const router = useRouter();
  
  return (
    <TouchableOpacity onPress={() => router.push('/profile')}>
      <Text>Перейти в профиль</Text>
    </TouchableOpacity>
  );
}
```

**Методы:**
- `router.push('/path')` - перейти на экран (можно вернуться назад)
- `router.replace('/path')` - заменить текущий экран (нельзя вернуться)
- `router.back()` - вернуться назад

#### 2. Настройка навигации в `_layout.js`

```javascript
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      <Stack.Screen 
        name="index" 
        options={{ title: 'Главная' }} 
      />
      <Stack.Screen 
        name="profile" 
        options={{ title: 'Профиль' }} 
      />
    </Stack>
  );
}
```

**Что здесь происходит?**
- `Stack` - тип навигации (стек экранов, как стопка карт)
- `Stack.Screen` - настройка каждого экрана
- `options` - настройки заголовка, цветов и т.д.

### Типы навигации

1. **Stack** - экраны накладываются друг на друга (как стопка)
2. **Tab** - вкладки внизу экрана
3. **Drawer** - боковое меню

## 🔄 Состояние (State)

### Что такое состояние?

**Состояние** - это данные, которые могут изменяться и влияют на отображение компонента.

**Аналогия:** Представь переменную, которая при изменении автоматически обновляет экран.

### useState - хук для состояния

```javascript
import { useState } from 'react';

function MyComponent() {
  const [count, setCount] = useState(0);
  
  return (
    <View>
      <Text>{count}</Text>
      <TouchableOpacity onPress={() => setCount(count + 1)}>
        <Text>Увеличить</Text>
      </TouchableOpacity>
    </View>
  );
}
```

**Что здесь происходит?**
1. `useState(0)` - создаем состояние со значением 0
2. `count` - текущее значение
3. `setCount` - функция для изменения значения
4. При вызове `setCount` компонент **автоматически перерисовывается**

### Правила useState

1. **Не изменяй состояние напрямую:**
```javascript
// ❌ Плохо
count = count + 1;

// ✅ Хорошо
setCount(count + 1);
```

2. **Используй функцию для обновления:**
```javascript
// ✅ Если новое значение зависит от старого
setCount(prevCount => prevCount + 1);
```

### Пример из проекта (profile.js)

```javascript
const [name, setName] = useState('Иван');
const [email, setEmail] = useState('ivan@example.com');

<TextInput
  value={name}
  onChangeText={setName}  // Когда пользователь вводит текст, setName обновляет состояние
/>
```

**Что происходит:**
1. Пользователь вводит текст в поле
2. `onChangeText` вызывает `setName` с новым текстом
3. Состояние `name` обновляется
4. Компонент перерисовывается с новым значением
5. Поле показывает новый текст

**Это и есть реактивность React!**

## 📝 JavaScript vs TypeScript

### В чем разница?

#### JavaScript (JS/JSX)
- **Проще** - меньше синтаксиса
- **Меньше требований** - пишешь код и все работает
- **Расширения:** `.js`, `.jsx`

#### TypeScript (TS/TSX)
- **Сложнее** - нужно указывать типы
- **Безопаснее** - сложнее ошибиться
- **Расширения:** `.ts`, `.tsx`

### Пример разницы

#### JavaScript:
```javascript
function greet(name) {
  return `Привет, ${name}!`;
}

greet("Иван");  // ✅ Работает
greet(123);     // ✅ Работает (но может быть ошибка)
```

#### TypeScript:
```typescript
function greet(name: string): string {
  return `Привет, ${name}!`;
}

greet("Иван");  // ✅ Работает
greet(123);     // ❌ Ошибка! Ожидается string
```

### Что выбрать?

**Для новичков:** JavaScript
- Меньше синтаксиса
- Быстрее начать
- Меньше ошибок компиляции

**Для серьезных проектов:** TypeScript
- Меньше багов
- Лучшая поддержка IDE
- Проще работать в команде

### В этом проекте

Проект использует **JavaScript** для простоты. Если хочешь TypeScript:
1. Переименуй файлы: `.js` → `.ts`, `.jsx` → `.tsx`
2. Добавь типы к параметрам
3. Установи TypeScript: `npm install --save-dev typescript`

**Но для обучения JavaScript достаточно!**

## ❓ Часто задаваемые вопросы

### Q: Почему не работает навигация?
**A:** Убедись, что файлы находятся в папке `app/` и правильно названы.

### Q: Как изменить цвет заголовка?
**A:** В `app/_layout.js` в `options` добавь `headerTintColor: '#fff'`.

### Q: Почему стили не применяются?
**A:** Проверь синтаксис StyleSheet. Все свойства должны быть в camelCase (`backgroundColor`, не `background-color`).

### Q: Как добавить иконки?
**A:** Используй библиотеку `@expo/vector-icons` или `expo-icons`.

### Q: Можно ли использовать обычный CSS?
**A:** Нет, React Native использует только StyleSheet (похоже на CSS, но это не CSS).
